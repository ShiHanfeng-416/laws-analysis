# 个人法律助手（Legal-RAG）架构设计

| 项目 | 内容 |
| --- | --- |
| 版本 | v0.1（设计基线） |
| 日期 | 2026-10-04 |
| 上游文档 | `docs/需求文档.md`（FR 编号均指向该文档） |
| 技术栈 | LangChain / LlamaIndex 双引擎、FAISS、EmbeddingGemma-300M-LawVault（本地）/ bge-m3（在线）、OpenAI 兼容 LLM |

---

## 1. 总原则

1. **答案必须可溯源**：所有结论来自本地法条原文，检索不到就明说无依据（对应 FR-5.2）。
2. **双引擎对等**：LangChain 与 LlamaIndex 是同一抽象的两个实现，不存在主从关系；共享同一份索引文件（FR-3.5）。
3. **配置唯一入口**：只有 `config.py` 允许读环境变量；密钥只进 `.env`（gitignore），`.env.example` 永远只放占位符。
4. **能由代码推导的值不进配置**：如 embedding 维度由模型探测后写入索引指纹（FR-3.4），不做人工配置项。

---

## 2. 分层架构

```
L4 应用层   build_index.py / ask.py / review.py / app.py        ← CLI 与 UI 入口，不含业务逻辑
L3 引擎层   engines/langchain_engine.py / llamaindex_engine.py   ← 双实现，互不依赖
L2 数据层   loaders.py / splitters.py / embeddings.py / store.py ← 共享流水线，与引擎无关
L1 基础层   config.py / schemas.py / rules.yaml                 ← 被所有人依赖
```

### 2.1 依赖铁律

| 编号 | 规则 | 动机 |
| --- | --- | --- |
| R1 | 只允许上层 import 下层，禁止反向 | 防止循环依赖、保证可测性 |
| R2 | L1/L2 禁止 import langchain / llama_index | 共享层必须引擎中立，`store.py` 直接操作裸 `faiss` 库 |
| R3 | 两个 engine 互不 import，均实现 `engines/base.py` 接口 | 应用层靠 `--engine lc|li` 切换 |
| R4 | 应用层只认 `base.py` 接口，不认识具体引擎 | 引擎可替换、可对比（AC-5） |

## 4. 模块契约

### 4.1 L1 基础层

| 模块 | 职责 | 输入 | 输出 | 禁忌 |
| --- | --- | --- | --- | --- |
| `config.py` | 读 `.env`，集中全部配置常量 | `.env` | `get_settings() -> Settings`（frozen dataclass，`lru_cache` 单例） | 不验证 key 有效性；不 import 任何引擎库；无业务逻辑 |
| `schemas.py` | 定义全项目通用数据模型 | — | `LawDocument / LawChunk / Citation / AnswerResult / ReviewFinding` | 不含 I/O |
| `rules.yaml` | 合同风险规则库（FR-6.3/6.4） | 人工编辑 | 规则条目：`模式 / 风险等级 / 说明 / 关联法条 / 建议改法` | 不写死在代码里 |

`config.py` 要点：

- 模块级 `PROJECT_ROOT = Path(__file__).resolve().parents[1]`，`load_dotenv(PROJECT_ROOT / ".env")`（不依赖 cwd）
- 路径类键（`EMBED_MODEL_PATH / LAWS_DIR / INDEX_DIR`）存相对值，构造 Settings 时拼成绝对路径
- `EMBED_PROVIDER` 为 `Literal["local", "api"]`，非法值抛异常
- 整型键用 `_env_int(name, default)` 读取，非法数字回退默认值

### 4.2 L2 数据层（建库流水线：loaders → splitters → embeddings → store）

| 模块 | 职责 | 输入 | 输出 |
| --- | --- | --- | --- |
| `loaders.py` | 扫描 `data/laws/*.txt` + 同名 `*.meta.json`，合并元数据；PDF/DOCX 解析为独立函数惰性 import | 语料目录 | `list[LawDocument]` |
| `splitters.py` | 以「第X条 / 章 / 节」为边界切分（FR-2.2），长条按句兜底；长度上限/重叠由配置驱动 | `LawDocument` | `list[LawChunk]` |
| `embeddings.py` | 工厂：provider=local 加载 LawVault（sentence-transformers）；provider=api 走 OpenAI 兼容接口。运行时探测维度与模型名 | `Settings` | 统一 embed 接口（`embed_texts / embed_query`） |
| `store.py` | 裸 FAISS 写读（`faiss.write_index/read_index`）+ 自管 docstore + 增量更新（按文件 hash，FR-1.6）+ 模型指纹校验（FR-3.4） | `LawChunk` + 向量 | `data/index/` 三件套（见 §6） |

### 4.3 L3 引擎层

| 模块 | 职责 |
| --- | --- |
| `engines/base.py` | 抽象接口：`QAEngine.ask(question: str, history: list) -> AnswerResult`；可选 `review(contract_text) -> list[ReviewFinding]` |
| `engines/langchain_engine.py` | 检索（FAISS retriever）→ LCEL 链 `Prompt \| LLM \| StrOutputParser`（FR-5.4） |
| `engines/llamaindex_engine.py` | `FaissVectorStore` 包装共享索引 → `VectorStoreIndex.from_vector_store` → `QueryEngine`（FR-5.5） |

两引擎共享 `AnswerResult` 输出模型与同一套 Prompt 约束（只依据上下文作答），保证输出格式一致、可直接对比。

### 4.4 L4 应用层

| 模块 | 职责 |
| --- | --- |
| `build_index.py` | 组装 L2 流水线建库；负责 `mkdir data/index`；增量更新入口（AC-1） |
| `ask.py` | 问答 CLI：`pixi run ask "…" [--engine lc|li]`；多轮对话（FR-5.7） |
| `review.py` | 审查 CLI：规则库命中 + RAG 依据检索，输出风险清单（FR-6.2） |
| `app.py` | Streamlit UI：对话 + 合同粘贴 + 引用折叠（M7） |

## 5. 关键设计决策（ADR）

### D1 中间格式自有化（schemas.py）

**决策**：L2 层流转使用自有 dataclass（`LawDocument/LawChunk`），不用 LangChain `Document` 或 LlamaIndex `TextNode` 作为通用格式，引擎侧各自做一行转换。

**理由**：双引擎对等（避免以某框架为中心）；共享层可独立于两个框架测试与复用。

**替代方案**（否决）：直接用 LangChain Document——会让 LlamaIndex 侧永久从属，且共享层被迫依赖 langchain。

### D2 store.py 引擎中立（FR-3.5 的根基）

**决策**：`store.py` 直接操作裸 `faiss`（`IndexFlatIP` + 归一化向量 = 余弦相似度），文本与元数据自管 `docstore.json`，模型指纹写 `index_meta.json`。引擎侧适配：

- LangChain：`FAISS(embedding_function, index, docstore, index_to_docstore_id)` 手动构造
- LlamaIndex：`FaissVectorStore(faiss_index=index)` + `StorageContext.from_defaults(docstore=…)`

**理由**：两框架官方落盘格式互不兼容（LC 存 `index.pkl`，LI 存自有 `docstore.json` 结构），“同一份索引文件”只能靠自管三件套实现。

### D3 统一输出契约

**决策**：双引擎输出统一为 `AnswerResult`（结论 / 依据引用 / 行动建议 / 免责声明，FR-5.6），并带 `engine` 字段标记来源。

**理由**：格式一致靠共享模型而非“prompt 写得一样”；AC-5 对比评测直接 diff 两份 `AnswerResult`。

### D4 Embedding 双通道，本地为默认

**决策**：`EMBED_PROVIDER=local|api`。local = `models/lawvault`（EmbeddingGemma-300M-LawVault，768 维，max_seq 1024，F32 权重 1.2GB，CPU 可跑）；api = OpenAI 兼容接口（默认 bge-m3，1024 维）。

**理由**：本地离线、免费、法律领域微调实测有效（模型卡评测：口语化法律咨询 Top-1 92%）；在线通道留作对照与大批量加速。

**注意**：模型下载只走 HuggingFace 完整版（`ByronLeeee/EmbeddingGemma-300M-LawVault`，主权重 1.21GB）；ModelScope 同名仓库权重损坏（根目录仅 9MB、缺主干张量），不可用。VPN 不在时设 `HF_ENDPOINT=https://hf-mirror.com` 走镜像。

**格式约定**：LawVault 训练时文档输入格式为 `title: {法规名} | text: {内容}`，推理必须逐字对齐——`LawChunk.embed_text` 属性按此拼接（仅用于向量化，展示与引用仍用纯正文）。

### D5 配置集中与密钥安全

**决策**：`.env`（gitignore）放真实密钥；`.env.example` 只放占位符；被 ignore 的目录（`data/index/`）由代码运行时自建。

## 6. 索引文件布局（`data/index/`，由 store.py 管理）

| 文件 | 内容 | 说明 |
| --- | --- | --- |
| `index.faiss` | 归一化向量的 `IndexFlatIP` | 两引擎共读，禁止各自另存格式 |
| `docstore.json` | `{chunk_id: {text, law_title, article_no, section, effective_date, source_url, file_hash}}` | 文本与元数据，检索结果组装引用用 |
| `index_meta.json` | `{embedding_model, dim, chunk_size, chunk_overlap, built_at, files: {法规文件名: hash}}` | 指纹校验（模型/维度不一致拒绝加载）与增量更新依据 |

增量更新流程：扫描 `data/laws/` 计算 hash → 与 `index_meta.json` 比对 → 仅对变动法规重新 load/split/embed → 删除旧 chunk 后合入索引。

## 7. 数据模型草案（schemas.py）

```python
@dataclass(frozen=True)
class LawDocument:            # loaders 输出
    doc_id: str              # 文件名去扩展名，如 "minfadian"
    title: str               # 法规名（来自 meta.json）
    law_type: str            # 法律/行政法规/司法解释/部门规章
    issued_by: str
    publish_date: str
    effective_date: str
    source_url: str
    text: str                # 全文

@dataclass(frozen=True)
class LawChunk:              # splitters 输出、store 写入
    chunk_id: str            # f"{doc_id}:{article_no}:{seq}"
    doc_id: str
    law_title: str
    article_no: str          # 如 "第七百零四条"；非条文切分为 ""
    section: str             # 章节名
    text: str                # 纯正文（展示/引用用）
    @property
    def embed_text(self) -> str:
        return f"title: {self.law_title} | text: {self.text}"   # 对齐 LawVault 训练格式

@dataclass(frozen=True)
class Citation:              # 引用（FR-5.3）
    law_title: str
    article_no: str
    quote: str               # 原文摘要，必须能在 data/laws 逐字查到（AC-2）
    source_url: str
    effective_date: str

@dataclass(frozen=True)
class AnswerResult:          # 双引擎统一输出（FR-5.5/5.6）
    conclusion: str
    citations: list[Citation]
    action_steps: list[str]
    disclaimer: str          # 固定免责声明（AC-6）
    engine: str              # "langchain" | "llamaindex"

@dataclass(frozen=True)
class ReviewFinding:         # 合同审查输出（FR-6.2）
    clause_text: str         # 条款原文
    risk_level: str          # 高/中/低
    explanation: str
    legal_basis: list[Citation]
    suggestion: str
```
