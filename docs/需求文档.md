# 个人法律助手（Legal-RAG）需求文档

| 项目 | 内容 |
| --- | --- |
| 项目名称 | 个人法律助手 —— 基于 RAG 的多文档智能问答系统 |
| 版本 | v0.1（需求基线） |
| 定位 | 担任**初级法律顾问**：对个人日常遇到的合同与消费纠纷给出「有法条依据」的初步判断，提示风险点与下一步动作 |
| 技术栈 | LangChain / LlamaIndex、FAISS、Embedding、LLM（OpenAI 兼容协议） |
| 环境管理 | pixi（Windows 无 Docker 场景下替代 conda+pip 的方案） |

---

## 1. 背景与目标

### 1.1 背景

* 租房、买车、办卡、网购等日常场景中，合同条款往往埋有不利条款（押金不退、违约金畸高、格式条款加重对方责任、售后三包被限缩等）。
* 通用大模型回答法律问题时会**编造法条**，不能直接采信。
* 因此需要一套「答案必须来自本地真实法条原文」的检索增强生成（RAG）系统。

### 1.2 目标（本项目要解决的）

| 编号 | 目标 |
| --- | --- |
| G1 | 建立一份**可离线复用**的本地法规语料库（已收录法律、行政法规、司法解释、部门规章） |
| G2 | 用户用自然语言提问，系统返回**可溯源到具体条文**的回答 |
| G3 | 针对**合同文本**做风险审查，逐条指出「坑」并给出依据与修改建议 |
| G4 | 双引擎实现（LangChain 与 LlamaIndex），同一份 FAISS 索引可复用，便于对比与迁移 |

### 1.3 非目标（明确不做）

* **不替代执业律师**，不生成具有法律效力的意见书，所有输出必须带免责声明。
* 不做判例检索（裁判文书网数据获取与合规成本高，二期再评估）。
* 不做地方性法规的全国覆盖（仅按用户所在城市按需增补）。

## 2. 用户与使用场景

### 2.1 用户画像

单一主要用户（系统所有者），具备基本技术能力，法律专业知识为零到初级。

### 2.2 核心场景（User Story）

| ID | 场景 | 用户故事 | 期望结果 |
| --- | --- | --- | --- |
| US-1 | 签约前审查 | 我把房东给的租赁合同贴进去，帮我看看哪里有问题 | 逐条列出风险条款（等级 + 依据法条 + 修改建议） |
| US-2 | 签约前审查 | 4S 店的购车合同/定金协议，有哪些坑 | 同上，重点提示定金罚则、三包、交付时间、加装与保险绑定 |
| US-3 | 事实问答 | 房东不退押金怎么办 | 给出法律分析 + 适用条文 + 可操作的维权步骤 |
| US-4 | 条文检索 | 租赁合同里「提前退租扣两个月租金」合法吗 | 定位到民法典/司法解释条文并解释效力 |
| US-5 | 消费维权 | 新车 3 个月发动机异响，能退换吗 | 引用《家用汽车产品修理更换退货责任规定》三包条款 |
| US-6 | 知识库维护 | 新增了一部法规，怎么进库 | 一条命令增量更新索引，不重建全库 |

## 3. 功能需求

### 3.1 语料获取与预处理（FR-1）

| ID | 需求 | 说明 |
| --- | --- | --- |
| FR-1.1 | 支持按目录批量加载文档 | `DirectoryLoader`（LangChain）/ `SimpleDirectoryReader`（LlamaIndex），统一为 `Document` |
| FR-1.2 | 支持 TXT / Markdown / PDF / DOCX 多种格式 | 已落入 `data/laws/*.txt`；后续可直接放入原始 PDF/DOCX |
| FR-1.3 | 法规下载脚本可复现 | `scripts/fetch_laws.py`：国家法律法规数据库（检索 → 元数据 → 正文 docx/doc）+ 中国政府网补录部门规章 |
| FR-1.4 | 保留元数据 | 每部法规带 `title / law_type / issued_by / publish_date / effective_date / source_url`，写入 `*.meta.json` |
| FR-1.5 | 元数据进入 Document | 切分后每个 chunk 携带来源法规名、效力层级、施行日期，供检索过滤与答案引用 |
| FR-1.6 | 可增量更新 | 依据文件 hash/修改时间判断是否需要重建，未变动直接复用已有索引 |

### 3.2 文本切分（FR-2）

| ID | 需求 |
| --- | --- |
| FR-2.1 | 默认按固定长度 + 重叠切分（默认 600 字 / 重叠 120 字） |
| FR-2.2 | **法条感知切分**：优先以「第X条」「章」「节」为边界，避免把一条法条切碎；长条按句再切 |
| FR-2.3 | 每个 chunk 头部注入该法规标题与章节名，避免跨法规语义混淆 |
| FR-2.4 | 切分参数可通过环境变量配置（`CHUNK_SIZE` / `CHUNK_OVERLAP`） |

### 3.3 向量化与索引（FR-3）

| ID | 需求 |
| --- | --- |
| FR-3.1 | 使用中文 Embedding 模型把 chunk 转向量，默认走 OpenAI 兼容接口（`BAAI/bge-m3` 等） |
| FR-3.2 | 可选本地离线 Embedding（`sentence-transformers` + `BAAI/bge-small-zh-v1.5`），不出网 |
| FR-3.3 | 向量写入 FAISS，落盘 `data/index/`，支持本地持久化与重复复用 |
| FR-3.4 | Embedding 维度/模型写入索引元信息，模型不一致时**拒绝加载并提示重建** |
| FR-3.5 | LangChain 与 LlamaIndex 共享同一份 FAISS 索引文件，避免重复建库 |

### 3.4 检索（FR-4）

| ID | 需求 |
| --- | --- |
| FR-4.1 | query 向量化后取 top-k 相关片段（默认 k=6） |
| FR-4.2 | 支持元数据过滤（如只在「租房」类或「法律/行政法规」层级内检索） |
| FR-4.3 | 支持混合检索：向量召回 + BM25 关键词召回融合（法条编号等精确词命中差是纯向量的弱点） |
| FR-4.4 | 检索结果按相关度排序，并做去重（同一条文的多段只保留最优段） |
| FR-4.5 | 返回片段必须包含来源法规名与条文号 |

### 3.5 问答与生成（FR-5）

| ID | 需求 |
| --- | --- |
| FR-5.1 | Prompt 模板注入「上下文 + 用户问题」，**强制只依据上下文回答** |
| FR-5.2 | 检索不到依据时，明确回答「知识库中没有相关依据」，禁止凭记忆作答 |
| FR-5.3 | 回答必须给出**引用列表**：法规名 + 条文号 + 原文摘要 + 来源链接 |
| FR-5.4 | LangChain 侧使用 LCEL 组链：`Prompt \| LLM \| StrOutputParser` |
| FR-5.5 | LlamaIndex 侧提供等价实现，二者输出格式一致，便于对比 |
| FR-5.6 | 输出结构化：`结论 / 依据 / 行动建议 / 免责声明` 四段 |
| FR-5.7 | 支持多轮对话（保留最近 N 轮作为上下文，但检索仍基于当前问题改写后的 query） |

### 3.6 合同风险审查（FR-6，核心差异化功能）

| ID | 需求 |
| --- | --- |
| FR-6.1 | 支持粘贴合同全文或上传文件（TXT/PDF/DOCX） |
| FR-6.2 | 输出风险清单：`条款原文 / 风险等级（高-中-低）/ 问题说明 / 依据法条 / 建议改法` |
| FR-6.3 | 内置常见「坑」规则库（作为检索增强的补充，提高召回）：<br>· 押金/定金条款（定金罚则上限 20%）<br>· 违约金畸高（超过实际损失 30% 可请求调减）<br>· 单方解除权不对等<br>· 免除己方责任、加重对方责任、排除对方主要权利的格式条款（无效）<br>· 租房：租期超 20 年部分无效、维修义务转嫁、转租禁止、涨租约定<br>· 买车：三包期限被缩短、强制店内上险、加装加价、交付时间无约定、定金不退条款 |
| FR-6.4 | 规则库为可编辑配置（`law_rag/rules.yaml`），不写死在代码里 |
| FR-6.5 | 若合同涉及知识库未覆盖领域，明确提示「未覆盖」而不是硬编 |

### 3.7 交互形态（FR-7）

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-7.1 | CLI：`pixi run ask "…"`、`pixi run review 合同.txt` | P0 |
| FR-7.2 | 本地 Web UI（Streamlit / Gradio）：对话 + 合同粘贴框 + 引用折叠展示 | P1 |
| FR-7.3 | 引用可点击展开法条原文 | P1 |
| FR-7.4 | 一键复制回答、导出 Markdown 审查报告 | P2 |

## 4. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 准确性 | 所有结论必须能溯源到知识库原文；无法溯源时明确说「无依据」 |
| 时效 | 法规会修订：每个回答展示所引法规的**公布/施行日期**；提供 `check-update` 任务比对线上版本 |
| 性能 | 33 部法规（约 110 万字）建库 < 5 分钟；单次问答端到端 < 15 秒（不含 LLM 网络耗时） |
| 成本 | 优先使用可按量付费的国产模型与 Embedding；本地 Embedding 作为可选降级方案 |
| 可复现 | `pixi.lock` 锁定全部依赖；`data/laws` 可由脚本一键重建 |
| 隐私 | 全部数据本地存储；上传合同仅在本地处理，不随日志外发 |
| 可维护 | 配置集中在 `.env` 与 `law_rag/config.py`，无硬编码密钥 |
| 合规 | 输出固定带免责声明；语料仅用官方公开来源，保留来源 URL |

| 分类 | 法规 |

| 租房 | 城镇房屋租赁合同司法解释、住房租赁条例、商品房屋租赁管理办法、城市房地产管理法、物业管理条例、商品房买卖合同司法解释 |
| 买车 | 家用汽车产品修理更换退货责任规定、汽车销售管理办法、二手车流通管理办法、缺陷汽车产品召回管理条例、道路交通安全法、交强险条例、保险法 |
| 维权程序 | 民事诉讼法、仲裁法、市场监督管理投诉举报处理暂行办法 |
| 常用补充 | 劳动合同法、民法典担保制度司法解释 |

### 5.2 数据来源

* 国家法律法规数据库 `https://flk.npc.gov.cn`（法律 / 行政法规 / 司法解释，权威原文）
* 中国政府网 `https://www.gov.cn`（部门规章，国务院公报与政策库）
* 每部法规附 `*.meta.json`，记录制定机关、公布/施行日期、效力层级、来源 URL

### 5.3 数据扩充路径

1. 在 `scripts/fetch_laws.py` 的 `LAWS`（官方库）或 `MANUAL`（gov.cn）清单里加一行即可；
2. 或把任意 PDF/DOCX/TXT 直接丢进 `data/laws/`，建库时自动纳入。

## 6. 系统架构

```
data/raw/                  # 原始 docx/pdf（留档）
data/laws/                 # 清洗后的法规正文 + meta.json  ← 唯一语料入口
        │
        ├─ loaders         # DirectoryLoader / SimpleDirectoryReader
        ├─ splitters       # 法条感知切分 + 固定长度兜底
        ├─ embedder        # OpenAI 兼容 / 本地 sentence-transformers
        └─ store           # FAISS 落盘 data/index/
                              ▲ 同份索引被两套引擎复用
        ┌───────────────────┴───────────────────┐
   LangChain 链路                          LlamaIndex 链路
   Prompt | LLM | StrOutputParser          VectorStoreIndex + QueryEngine
        └───────────────────┬───────────────────┘
                       回答 + 引用 + 免责声明
```

### 6.1 目录结构

```
law-rag/
├── pixi.toml / pixi.lock     # 环境与依赖锁定
├── .env.example              # API 配置模板
├── scripts/fetch_laws.py     # 法规下载
├── law_rag/
│   ├── config.py             # 环境变量与常量
│   ├── loaders.py            # 文档加载 + 元数据注入
│   ├── splitters.py          # 切分策略
│   ├── embeddings.py         # Embedding 工厂（在线/本地）
│   ├── store.py              # FAISS 读写与增量更新
│   ├── rules.yaml            # 合同风险规则库
│   ├── build_index.py        # 建库 CLI
│   ├── ask.py                # 问答 CLI
│   └── review.py             # 合同审查 CLI
├── data/  laws/ raw/ index/
└── docs/  需求文档.md
```

## 7. 技术方案要点

| 环节 | 选型 | 理由 |
| --- | --- | --- |
| 环境 | **pixi** | Windows 无 Docker；pixi 用 conda 管 Python 与二进制依赖、用 PyPI 管生态库，锁文件跨平台可复现，一条 `pixi install` 复现环境 |
| 向量库 | FAISS | 单机、无服务、索引可落盘复用，契合「减少重复建库」 |
| Embedding | `BAAI/bge-m3`（在线）/ `bge-small-zh-v1.5`（本地） | 中文语义检索效果与成本平衡 |
| 编排 | LangChain（LCEL）+ LlamaIndex | 双实现对比；LCEL 组链简洁，LlamaIndex 索引抽象更强 |
| 切分 | 法条感知 + 固定长度兜底 | 法律文本结构性极强，纯固定长度会切断条文 |
| 检索 | 向量 + BM25 混合 | 法条编号、专有名词的精确匹配是纯向量的短板 |

## 9. 验收标准

| 编号 | 标准 |
| --- | --- |
| AC-1 | `pixi run build-index` 能对 `data/laws/` 33 部法规建库，重复执行时未变动文件不重建 |
| AC-2 | 提问「房东不退押金怎么办」，回答中引用的条文能在 `data/laws/` 原文中逐字查到 |
| AC-3 | 提问知识库外的问题（如「怎么写遗嘱」未收录时），回答明确说明无依据，不编造法条 |
| AC-4 | 对一份含「提前退租扣两个月租金」「押金不退」的租赁合同，审查结果至少命中 2 条高风险并给出法条依据 |
| AC-5 | LangChain 与 LlamaIndex 两条链路在同一组 10 个问题上，引用到的法规集合重合度 ≥ 70% |
| AC-6 | 所有回答末尾包含免责声明与所引法规的施行日期 |

## 10. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| LLM 幻觉 | 高，法律场景不可接受 | 强制基于上下文；无依据必须声明；输出必带引用 |
| 法规修订导致语料过期 | 中 | 每条引用展示施行日期；提供 `check-update` 比对官方库 |
| 部门规章来源不统一 | 中 | 统一走 gov.cn 公报原文，记录 source_url 便于核对 |
| 切分切断法条 | 中 | 法条感知切分 + chunk 头部注入标题 |
| Embedding 模型更换 | 中 | 索引记录模型与维度，不一致时拒绝加载 |
| 站点反爬 / WAF | 低 | 下载脚本带会话、退避重试与限速；语料已落盘可长期复用 |
| 用户误当作正式法律意见 | 高 | 固定免责声明 + 输出中提示必要时咨询执业律师 |
